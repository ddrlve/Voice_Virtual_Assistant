# ARIA - Advanced Responsive Intelligence Assistant

A voice-controlled desktop assistant written in Python. ARIA listens through your microphone, converts speech to text with Google's speech recognition API, matches the text against a set of built-in command categories, and replies out loud using text-to-speech.

- Version: 2.0.0
- Language: Python 3.9+
- Platform: Windows, macOS, Linux (tested primarily on Windows)

## Features

- Speech recognition using the `speech_recognition` library (Google Web Speech API, requires internet access)
- Text-to-speech output using `pyttsx3` (runs offline, uses the operating system's voice engine)
- Automatic microphone calibration for ambient noise on startup
- Command categories: greetings, time and date, schedule lookup, weather lookup, web search, calculator, system status, contact lookup, media search (YouTube), and exit
- Color-coded console output for readability
- Session statistics (duration and number of exchanges) printed on exit
- Schedule and contact data persisted to local JSON files, auto-created on first run

## Requirements

- Python 3.9 or later (the code uses the `tuple[str, str]` return type syntax, which requires 3.9+)
- A working microphone
- An internet connection (required for speech recognition and for live weather data)
- Windows: `launch_aria.bat` is provided for a one-click setup and run
- pip packages listed in `requirements.txt`

## Installation

1. Clone or download the repository, then move into the project folder:

   ```bash
   git clone <your-repo-url>
   cd "Voice Virtual Assistant"
   ```

2. Create and activate a virtual environment (recommended, optional):

   ```bash
   python -m venv .venv
   # Windows
   .venv\Scripts\activate
   # macOS / Linux
   source .venv/bin/activate
   ```

3. Install the dependencies from `requirements.txt`:

   ```bash
   pip install -r requirements.txt
   ```

   `pyaudio` is required for microphone access. On Windows it usually installs from a prebuilt wheel without issues; on macOS/Linux you may need to install `portaudio` first (see [Troubleshooting](#troubleshooting)).

## Configuration

ARIA works out of the box with demo weather data and no configuration file. Create a `.env` file only if you want live weather data or plan to enable API-based features later.

1. Create a file named `.env` in the project root:

   ```env
   WEATHER_API_KEY=your_openweathermap_api_key
   OPENAI_API_KEY=your_openai_api_key
   ```

2. `WEATHER_API_KEY` is optional. Get a free key from [OpenWeatherMap](https://openweathermap.org/api). Without a key (or with the value left as `demo_key`), ARIA returns a fixed demo weather reading instead of a real forecast.
3. `OPENAI_API_KEY` is read into configuration but is not currently used by any feature. It is reserved for a possible future AI chat integration.

## Running ARIA

### Option A: Run directly with Python

```bash
python aria_voice_assistant.py
```

### Option B: Use the Windows launcher

Double-click `launch_aria.bat`, or run it from a terminal:

```bat
launch_aria.bat
```

The launcher will:

1. Check that Python is installed and on `PATH`.
2. Create a `.venv` virtual environment if one does not already exist.
3. Activate the virtual environment and install dependencies.
4. Create a default `.env` file if one is missing.
5. Run a quick check that the microphone and text-to-speech engine are reachable.
6. Start `aria_voice_assistant.py`.

### What happens on startup

1. ARIA calibrates the microphone against background noise (stand still and stay quiet for about a second).
2. A banner and the list of available command categories are printed to the console.
3. ARIA speaks a greeting and starts listening.
4. Each cycle: ARIA listens for a few seconds, transcribes what you said, prints and speaks a response, then listens again.
5. Say an exit phrase (for example "goodbye" or "exit") to end the session. Session statistics are printed when ARIA stops, including via Ctrl+C.

## Voice Commands

Speak naturally; ARIA matches on keywords contained anywhere in what you say, not on exact phrases.

| Category      | Example phrases                               | What it does                                   |
| ------------- | --------------------------------------------- | ---------------------------------------------- |
| Greetings     | "Hello", "Hi ARIA", "Good morning"            | Returns a time-appropriate greeting            |
| Time and Date | "What time is it?", "What's the date?"        | Reads the current time or date                 |
| Schedule      | "What's my schedule?", "Any meetings?"        | Reads out entries from `schedule.json`         |
| Weather       | "How's the weather?", "Weather in Tokyo"      | Reads weather for a city (defaults to Jakarta) |
| Search        | "Search for Python tutorials"                 | Opens a Google search in your default browser  |
| Calculator    | "Calculate 25 times 4", "What's 100 plus 50?" | Evaluates a basic arithmetic expression        |
| System        | "System status", "Computer performance"       | Reports CPU, memory, and battery status        |
| Contacts      | "Call Egi", "Contact Sophie"                  | Looks up an entry from `contacts.json`         |
| Media         | "Play some jazz music"                        | Opens a YouTube search for the requested song  |
| Exit          | "Goodbye", "Quit", "Exit"                     | Says goodbye and ends the session              |

Any phrase that doesn't match a category falls back to a generic help message listing what ARIA can do.

## Data Files

### schedule.json

A list of appointment objects, read on startup. Edit it directly to change today's schedule:

```json
[
  {
    "time": "09:00",
    "title": "Team Meeting",
    "location": "Conference Room",
    "priority": "high"
  }
]
```

### contacts.json

A dictionary keyed by a short lowercase name, read on startup. Edit it directly to add or change contacts:

```json
{
  "john": {
    "name": "John Doe",
    "phone": "+1-555-0123",
    "email": "john@example.com"
  }
}
```

Both files are auto-created with sample entries if they don't already exist, so you can also just run ARIA once and edit the generated files afterward.

## Customization

Basic personalization is done by editing variables directly in `aria_voice_assistant.py`, inside `AriaAssistant.__init__`:

```python
self.user_name = "Your Name"           # Name ARIA addresses you by
self.assistant_name = "ARIA"           # Assistant's spoken name
self.config = {
    "voice_rate": 180,                 # Speech speed
    "voice_volume": 0.9,               # Volume (0.0 to 1.0)
    "listen_timeout": 5,               # Seconds to wait for speech before timing out
    ...
}
```

There is currently no configuration file for these values; they must be changed in the source file.

## Troubleshooting

**Microphone not detected or not working**

```bash
python -c "import speech_recognition as sr; print(sr.Microphone.list_microphone_names())"
```

If the list is empty, check your operating system's microphone permissions and default input device.

**No speech output**

- Check system volume and that a playback device is connected.
- Confirm `pyttsx3` initializes without error: `python -c "import pyttsx3; pyttsx3.init()"`.

**Speech recognition fails or times out**

- Confirm you have an active internet connection; recognition uses the Google Web Speech API.
- Speak within the configured `listen_timeout` window (5 seconds by default) after "Listening..." appears.
- Reduce background noise, or increase `listen_timeout` in the source file.

**`pyaudio` fails to install**

- Windows: install a matching prebuilt wheel from PyPI, or install via `pipwin install pyaudio` if `pip install pyaudio` fails.
- macOS: `brew install portaudio` before `pip install pyaudio`.
- Linux (Debian/Ubuntu): `sudo apt-get install portaudio19-dev` before `pip install pyaudio`.

**Import errors on startup**

```bash
pip install --upgrade -r requirements.txt
```

## Known Limitations

- The calculator uses Python's `eval()` after filtering the input to a restricted character set; it is meant for quick arithmetic, not as a hardened expression parser.
- Contact "calls" only read out the stored phone number; ARIA cannot place an actual phone call.
- Media commands open a YouTube search in the browser; ARIA does not control playback directly.
- `conversation_history.json` and `user_preferences.json` are not wired up in the current version (see [Project Structure](#project-structure)).
